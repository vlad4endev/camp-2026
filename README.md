# Офлайн Кемп — лагерь 2026

Автономная панель лагеря: лендинг для участников, штаб для организаторов
и боты (Telegram / MAX). Работает без интернета — Node.js без зависимостей,
данные лежат в JSON-файлах рядом.

## Запуск

```bash
node server.mjs 8000
```

Или двойным щелчком по `start-panel.command` — поднимет сервер и откроет
дверь: `http://localhost:8000/enter.html`. Вход один на штаб и на стойку,
а куда пустить, решает роль.

Дверь работает в двух режимах и сама узнаёт, какой сейчас:

- **без интернета** — логин и пароль из `users.json` рядом с панелью,
  роль оттуда же. Ничего настраивать не надо, работает сразу.
- **с единой базой** — e-mail и пароль из Supabase Auth, роль из таблицы
  `staff`. Адрес проекта и ключ `anon` вводить не нужно: их отдаёт сервер
  из своего окружения ([supabase/README.md](supabase/README.md)).

Пароль в обоих случаях сверяет сервер, а не браузер: файл с хэшами по HTTP
не отдаётся вообще никому.

Боты (нужны токены):

```bash
TG_TOKEN=… MAX_TOKEN=… node bots.mjs
```

## Деплой

Публичный адрес — https://camp.offline-tambov.ru/. Без входа он раздаёт
только лендинг, приём записей и саму дверь. Установка, проверка границы и
повседневная выкладка — [deploy/README.md](deploy/README.md).

| Адрес | Что там |
|---|---|
| https://camp.offline-tambov.ru/ | лендинг для участников |
| https://camp.offline-tambov.ru/enter.html | **вход** — одна дверь на всех |
| https://camp.offline-tambov.ru/admin/ | штаб (ведёт на дверь) |
| https://camp.offline-tambov.ru/reseption/ | ресепшен (ведёт на дверь) |

**Одна страница входа.** Вводите e-mail и пароль — и оказываетесь там, где
работает ваша роль: регистратура на стойке, остальные в штабе. Пароли
держит Supabase Auth, роль — таблица `staff`.

Раньше вместо этого было два адреса под двумя паролями nginx, и роль
выбирал пароль. Иначе и не получалось: `auth_basic` срабатывает до отдачи
первого байта, то есть роль определялась раньше, чем могла загрузиться
страница входа. Теперь проверку делает сам `server.mjs` — он читает роль
из базы и ставит подписанную куку, — поэтому дверь может быть одна, а
разделение доступа стало строже: оно покрывает и запись файлов, и очередь
офлайн-правок, чего пароль на всю смену не делал.

Файлового входа (`users.json` с хэшами рядом с панелью) больше нет: два
списка доступа означали бы два разных ответа на вопрос «кто здесь
главный».

Код едет через GitHub: сервер сам подтягивает `main` каждые две минуты
(`camp-pull.timer`).

```bash
./deploy/publish.sh code   # выложить правки кода
```

Больше ноутбук в повседневной работе не нужен: доступ выдаётся в Supabase
(аккаунт) и в разделе «Пользователи» (роль), участники и лендинг правятся
в панели, история правок — в `backups/` на сервере.

На сервере процесс запускается с `CAMP_PUBLIC=1` — этот флаг снимает
привилегии с 127.0.0.1, потому что за nginx с этого адреса приходит весь
интернет. Права после этого даёт только вход.

```bash
node auth.mjs --selftest      # подпись куки: подменить роль или срок нельзя
```

## Единая база (Supabase)

Одна база на весь проект: штаб, стойка, лендинг и боты работают с одними
данными. Штаб и стойка — с любого устройства, лендинг и боты — через
`server.mjs`.

**Панелям база нужна обязательно**: вход идёт через Supabase Auth, другого
больше нет. Серверу — нет: без `SUPABASE_URL` он работает на JSON-файлах,
как раньше, и это же его поведение, когда база недоступна.

Файлы остаются: `participants.json`, `signups.json` и `camp.json`
становятся **зеркалом** базы, из которого читает сервер. Поэтому лагерь
по-прежнему работает без интернета — записи и правки ложатся в
`outbox.json` и досылаются, когда связь вернётся.

Установка, ключи, роли и проверки — [supabase/README.md](supabase/README.md).

```bash
node db.mjs --selftest        # перевод полей и механика очереди
```

## Синхронность

Штаб правит расписание и шлёт `PUT /camp` — только данные, без разметки.
Склеивает их в `landing.html` сервер, одной функцией на весь проект
(`camp.mjs`), и он же отдаёт их обратно на `GET /camp`.

Раньше панель присылала весь файл целиком, 295 КБ, из которых данными были
12. Разметку она при этом не правила, а отправляла — свою копию, прочитанную
на загрузке. Поэтому правка вёрстки жила ровно до следующего «Сохранить» из
вкладки, открытой раньше, и пропадала молча. Присылать стало нечем.

`PUT /landing.html` после этого убран совсем: разметку страницы лагеря не
перезаписывает через HTTP ни одна роль, включая главного. Она едет через
git, как `server.mjs`, `sw.js` и `bots.mjs`.

Открытая на телефоне страница спрашивает `GET /camp` при загрузке и
раз в 30 секунд, и если версия сменилась — пересобирает расписание,
объявления, тематику дня, мастер-классы и тексты **без перезагрузки**.
Тем же тактом обновляется занятость групп (`GET /seats`).
Регистрация на въезде (`reception.html`) перечитывает `participants.json`
каждые 4 секунды.

Сети нет — страница остаётся на данных, вшитых в файл: в лагере это норма.
На домене к этому добавляется задержка выкладки — до двух минут, пока
сервер тянет `main` из GitHub.

## Что где

| Файл | Что это |
|---|---|
| `landing.html` | Лендинг: расписание, объявления, мастер-классы, тематика дня |
| `enter.html` | Единая дверь: вход по логину и паролю, дальше по роли — в штаб или на стойку |
| `users.json` | Список доступа для лагеря без базы: логин, роль, хэш пароля. Читает его только сервер |
| `admin.html` | Штаб организатора |
| `reception.html` | Регистрация на въезде |
| `server.mjs` | HTTP-сервер с белым списком путей: в лагерную Wi-Fi не отдаёт ни админку, ни участников. Он же отдаёт `GET /camp` — данные лендинга, по которым открытые телефоны обновляются сами |
| `bots.mjs` | Боты Telegram и MAX |
| `auth.mjs` | Вход со стороны сервера: подпись и разбор куки с ролью, проверка токена у Supabase. Отдельным файлом — здесь тихая ошибка означает чужой вход, и проверять её надо не «заодно» |
| `db.mjs` | Единая база со стороны сервера: зеркало Supabase и очередь неотправленного. Без `SUPABASE_URL` выключен |
| `camp-db.js` | Единая база со стороны браузера: вход и данные для штаба и стойки. Один файл на две панели нарочно — правило «что считать изменением» должно быть одно |
| `camp-ui.js` | Общий слой панелей: помощники DOM, плашки, файл на сервере, разбор блока `CAMP`. Лежал копией в штабе и на стойке и тихо расходился — плашка держалась 2600 мс в одной и 2800 в другой. Браузерная пара к `camp.mjs`: свести их в одну нельзя (`<script>` не умеет ESM без сборки), поэтому `server.mjs --selftest` сверяет выражения между собой |
| `camp-ui.css` | Палитра лагеря, одна на три страницы. Только то, что совпадало дословно: плотность и скругления у штаба, стойки и двери разные по делу |
| `camp.mjs` | Блок `CAMP` со стороны сервера: разбор, склейка и версия. Одна регулярка вместо четырёх копий в `server.mjs`, `bots.mjs`, `admin.html` и `enter.html` |
| `supabase/` | Схема, перенос данных из JSON и проверка схемы на настоящем Postgres |
| `deploy/` | systemd-юниты, конфиг nginx, выкладка из GitHub |
| `sw.js`, `manifest.webmanifest`, `icons/` | PWA: лендинг ставится на телефон и работает офлайн |

## Чего нет в репозитории

`participants.json`, `signups.json`, `camp.json`, `outbox.json` и
`backups/` — живое состояние и зеркало базы. Создаются при первом запуске.
Пароли не хранятся здесь вовсе: вход — Supabase Auth.
